# 유성클리닝 현장 출력 프로그램

세탁공장 현장에서 날짜와 코스를 고른 뒤, 배송·세탁·마감용 문서를 바로 인쇄하는 웹 프로그램이다.
원본 데이터는 구글 시트 「세탁공장-현황지-거래처」이고, 시트에 붙은 Apps Script가 데이터 API 역할을 한다.

- 화면 주소: https://partybok-crypto.github.io/print_status_sheet/
- 배포: `master`에 push하면 GitHub Pages로 자동 배포된다(`.github/workflows/pages.yml`).

## 구성

| 파일 | 역할 |
| --- | --- |
| `index.html` | 현장 출력 화면(기본 진입). 배송날짜 → 코스 → 문서 → 인쇄 |
| `admin.html` | 관리·편집 화면. 배송순서 변경, 업체 추가·제외, 기사·코스 수정, 출력 기록 |
| `wash-core.js` | 세탁공정 배정 계산(수량 산정, 세탁기 4대 회차 배정, 검증). 화면과 분리된 순수 모듈 |
| `Code.gs` | Apps Script 데이터 API(`doGet`/`doPost`). **읽기 전용**이라 시트에 절대 쓰지 않는다 |
| `당일기사.gs` | 「세탁물 현황」 당일 배송기사 자동 기록. 시트에 쓰는 유일한 스크립트 |
| `tools/nametag_helper.ps1` | 이름표 인쇄 도우미. 현장 PC에서 TSC TTP-247로 직접 출력한다(127.0.0.1:9123) |
| `tests/wash-core.test.js` | `wash-core.js` 테스트. `node tests/wash-core.test.js`(외부 패키지 없음) |
| `reference/` | 세탁공정·합세탁 체크표 출력 견본 |

화면에서 바꾼 값(배송순서, 제외 업체, 기사·코스 수정 등)은 브라우저 `localStorage`에 날짜별로만 저장된다. 원본 시트에는 반영되지 않는다.

## 현장 화면 (`index.html`)

- 왼쪽 메뉴: 1. 배송날짜 선택 → 2. 코스 선택 → 3. 자주 사용하는 출력 → 4. 인쇄
  - "기타 출력"은 접혀 있고 "▸ 기타 출력"을 눌러 펼친다(펼침 상태 기억, 기타 문서를 고르면 자동으로 펼침).
  - 세로 860px 이하 화면(현장입력 PC: 1920×1080 150% 배율 → 크롬 화면 약 1280×580)에서는 자주 쓰는 출력이 2열이 되고 여백이 줄어, 스크롤 없이 인쇄 버튼까지 보인다.
  - 인쇄 버튼은 누를 수 있을 때 0.9초 간격으로 숨 쉬듯 커졌다 작아진다(윈도우 "애니메이션 효과 끄기" 설정과 무관).
  - 아래 작은 버튼 줄: 내용 수정 / 변경내역 테스트 출력 / 관리·편집
- 위쪽 상태: "데이터 HH:MM 불러옴"(초록) → 3분이 넘으면 "· 곧 새로 불러옴"(주황) → 실패 시 빨강. 옆에 작게 프로그램 버전 "v MM/DD HH:MM".

### 옛 데이터·옛 버전으로 인쇄하지 않게

- 인쇄 버튼을 누르면, 불러온 지 3분이 넘은 데이터는 먼저 다시 불러온 뒤 인쇄한다(버튼에 "최신 데이터 확인 중...").
- 화면이 보이고 1분 넘게 조작이 없으면 3분마다 데이터를 다시 불러온다.
- 서버 조회는 15초(1차)·15초·20초로 최대 3번 시도한다. 끝내 실패하면 마지막으로 성공한 데이터를 보여 주며 경고한다.
- 새 버전 확인
  - 배포 때 워크플로가 `index.html`·`admin.html`의 `__BUILD_ID__`(커밋 번호)와 `__BUILD_TIME__`(MM/DD HH:MM)을 채우고, `version.json`(`build`, `time`)을 만든다.
  - 열어 둔 창은 5분마다 `version.json`을 비교한다. 옛 버전이면 화면 80% 크기 안내창을 띄운다. 안내창 내용은 "프로그램이 업데이트 되었습니다 / 새로고침 해주세요 / (버전: 날짜 시간)"과 [새로고침] 버튼이고, 0.5초 간격으로 깜박인다.
  - 1분 넘게 조작이 없으면 자동으로 새로고침한다.
  - 인쇄 버튼을 누른 순간 옛 버전이면 인쇄하지 않고 안내창을 띄운다.
  - 로컬 실행(`__BUILD_ID__` 그대로)에서는 동작하지 않는다.
- Pages 배포에서 "No artifacts named github-pages"로 실패하는 일이 반복돼, 워크플로에 업로드 후 `sleep 20` 단계를 넣었다. 실패하면 `gh run rerun <id>`로 다시 돌린다.

## 출력 문서

자주 쓰는 출력

1. 현황지 + 주소지: 배송기사용, 2개 문서를 이어서 출력
2. 세탁공정: 세탁팀용 참고표, 세탁기 배정 포함
3. 합세탁 체크표: 마감자용
4. 마감자용 수량표 + 전체주소지: 세탁 마감용, 2개 문서를 이어서 출력
5. 출력 후 라벨코스 변경내역
6. 이름표 출력: 업체번호를 넣으면 라벨 프린터로 1장 출력

기타 출력: 주소지만, 현황지만, 마감자용 수량표만, 전체주소지만

### 현황지 모양 (`index.html`·`admin.html` 공통)

- **코스 첫 장 맨 위(첫 장에만):** 마감 담당 상자
  - "현황지 수량 이상 시 마감자에 바로 연락"(굵게)
  - 작은 안내: 포대·수건 수량이 다르거나 다른 거래처 수건이 섞이면 연락
  - 마감자 이름(28pt)·전화번호(22pt)
- **장마다 반복:** 파란 제목 줄(날짜·코스·기사), 열 제목
  - 본 표 위의 별도 머리 표에 마감 담당을 두고, 제목·열 제목은 본 표 `thead`에 둔다.
- **열 9개:** 배송순서 / 업체번호 / 약칭 / 업종 / 포대 배송 / 수건 배송 / 수거량 / 출고 / 오픈자 수량메모
  - 열 폭: `[9, 11, 12, 10, 14, 13, 10, 9, 12]`(%), 열 제목은 한 줄
  - 업체번호는 24pt 굵게(5글자 이상이면 18pt)
  - 마지막 열 제목은 "다음 날 날짜(요일) / 오픈자 수량메모 / 오픈자 이름"이다. 오픈 근무자가 손으로 적는 칸이다.
- **본 표 맨 아래 한 줄:** "총 개수 (마감자 기입)"과 포대·수건 칸(마감자 손기입)
- **그 아래:** 지원차 / 자차 / 총 수거량 표
- 인쇄할 때 `#printStatus` 안의 표는 모두 너비 100%라 오른쪽 끝이 맞는다(인쇄 CSS가 다른 표를 내용 맞춤으로 바꾸기 때문).
- 관리·편집 화면은 편집 화면 위쪽(출력 준비 안내 아래)에도 마감 담당 줄을 보여 준다.

## 원본 시트(읽는 위치)

- **세탁물 현황** (4행부터 업체 데이터)
  - A~F: 요일별 배송순서(코스코드). 1행 머리글에 "OO요일"이 들어 있다
  - H: 구역, I: 당일 기사(자동 기록), J: 합세탁, K: 업체번호, L: 약칭, M: 업종
  - N: 포대 배송, O: 수건 배송, P: 수거량, Q: 사이즈
  - T~Z: 월~일 배송 여부(값이 1이면 그 요일 배송)
  - AD: 주소, AE: 수거방식, AF: 배송 코멘트, AG: 거래처 번호
  - L2: 오늘 날짜, N1: 오늘 요일 (자동 기록)
- **거래처**: A 업체코드, X~AC 요일별 배송코스(화~일), AD~AI 요일별 배송기사(화~일)
  - 기사 이름은 이 열을 기준으로 정한다
- **업체별 수거량**: 세탁공정 수량 이력
- **외부 시트**
  - 현장입력 시트: 기사 앱·배송입력 앱 실수량
  - 「세탁공장-일정표」: 아래 "일정표에서 읽는 것" 참고

월요일은 휴무라 월요일 배송 열과 배정표가 없다.

### 일정표에서 읽는 것 (`Code.gs`)

일정표 「주차별 쉬프트」 탭 **위쪽 30행(이번 주 일정표)**의 날짜 블록(`MM-DD-요일` 칸 아래 포지션·이름 머리글)에서 찾는다.

| 항목 | 날짜 | 포지션 | 함수 |
| --- | --- | --- | --- |
| 현황지 마감 담당 | 현황지 날짜. 단 **화요일 현황지는 월요일**(세탁팀 화 휴무, 배송팀 월 휴무) | "마감" (여러 명) | `getClosers_`, `closerSourceDate_` |
| 마감 담당 전화번호 | - | 「근무자정보」 탭 E열(근무자명)·M열(핸드폰번호) | `attachPhones_` |
| 오픈자 수량메모 | 현황지 **다음 날**. 다음 날이 화요일이면 수요일 | "오픈" | `getOpener_`, `openerDateOf_` |
| 세탁공정 작성자 | 세탁일(다음 날) | 첫 출근자 | `getFirstWorkerName_` |

- 세탁공정 작성자는 지난 날짜일 때만 위쪽 200행까지 더 찾는다. 앞으로 올 날짜는 지난 블록에 있을 수 없어서다.
- 결과는 40분 기억한다(못 찾으면 10분).
- 트리거
  - `warmStatusCaches`: 06~22시에 30분마다 오늘·내일 결과를 미리 읽어 둔다. 설정은 `setupWarmCacheTrigger`
  - `onScheduleEdited`: 일정표 파일 "수정 시" 트리거. 일정표를 고치면 기억해 둔 결과를 바로 지운다. 설정은 `setupScheduleEditTrigger`
- 일정표에 그날 블록이 없으면 빈칸("________ 010-____-____", "______")으로 찍힌다.
- 「근무자정보」 탭에는 주민번호·계좌 열도 있으니, 읽을 때는 필요한 열만 지정한다.

## Apps Script 배포

- clasp 연결이 없어 시트의 확장 프로그램 → Apps Script 편집기에서 직접 고친다.
- 큰 코드를 클립보드로 붙여 넣으면 다른 프로그램이 클립보드를 덮어써 엉뚱한 내용이 들어갈 수 있다.
  - 편집기의 monaco 모델에 바뀐 구간만 `pushEditOperations`로 넣는다.
  - 로컬 파일과 길이·해시(FNV)를 비교한 뒤 저장한다.
- `Code.gs`를 바꾼 뒤에는 배포 → 배포 관리 → 기존 배포 수정 → **새 버전**으로 다시 배포해야 화면(`/exec`)에 반영된다.
  - 반영됐는지는 실제 `/exec` 응답으로 확인한다. 2026-11-29 기준 웹 앱 버전은 40이다.
- 트리거로만 도는 함수(`당일기사.gs`, `warmStatusCaches`, `onScheduleEdited`)는 저장만 하면 바로 적용된다.

## 당일 배송기사 자동 기록 (`당일기사.gs`)

「세탁물 현황」 탭의 세 칸에 쓴다.

- I4:I(마지막 행): 오늘 배송 나가는 업체 줄에 기사 이름을 적는다(전화번호 제외). 나머지 줄과 월요일은 비운다.
- L2: 오늘 날짜
- N1: 오늘 요일

당일 배송 판정과 기사 이름은 `Code.gs`의 `buildDayData_`와 같은 규칙을 쓴다. 「거래처」 기사 칸이 `---`(미배정)이면 비운다.

트리거(편집기에서 `setupTodayDriverTrigger`를 한 번 실행하면 둘 다 다시 걸린다)

- `updateTodayDrivers`: 매일 0시대(Asia/Seoul)에 실행
- `onEditTodayDrivers`: 아래 칸을 고치면 바로 다시 기록
  - 세탁물 현황: A~F, K, T~Z
  - 거래처: A, X~AI

## 테스트

```
node tests/wash-core.test.js
```

인쇄 모양은 playwright로 현황지를 PDF로 만들어(`page.pdf`, `prefer_css_page_size`) PyMuPDF로 그림을 떠서 확인했다.
이 방식은 실제 크롬 인쇄 창보다 장이 조금 더 잘 넘어가니, 장 수는 실제 인쇄로 확인한다.
